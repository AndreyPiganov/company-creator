# Company Creator

Локальная full-stack панель для создания вымышленных немецких B2B AI-компаний и неизменяемых версий их статических сайтов. Интерфейс и серверные API реализованы в одном приложении Next.js; отдельный Nest.js-сервис не входит в текущий MVP и может быть выделен следующим этапом.

> Все компании, сотрудники, адреса и продукты в приложении являются вымышленными проектными данными.

## Что умеет MVP

- создаёт двуязычную карточку компании на русском и немецком;
- генерирует контент локально, через OpenAI или через OpenRouter;
- позволяет проверить, отредактировать и утвердить карточку;
- при редактировании увеличивает ревизию и возвращает карточку в `draft`;
- создаёт из утверждённого снимка автономный трёхстраничный сайт на RU или DE;
- сохраняет каждую версию сайта неизменяемой;
- показывает сохранённый артефакт в preview и выдаёт тот же артефакт как ZIP;
- экспортирует каноническую карточку компании в JSON;
- содержит два идемпотентных примера и локальные синтетические портреты команды.

## Быстрый запуск через Docker

Требуются Docker Desktop и Docker Compose.

```bash
cp .env.example .env
docker compose up --build
```

Приложение откроется по адресу <http://localhost:3000>. Проверка готовности: <http://localhost:3000/api/health>.

Ключи не обязательны: локальный генератор и готовые примеры работают без сети. База и сайты хранятся в Docker volume `company_creator_data` и не пропадают после обычного `docker compose down`.

Остановить приложение:

```bash
docker compose down
```

Для полного удаления локальных данных требуется отдельная явная команда `docker compose down -v`.

## Рабочий сценарий

1. Откройте «Новая компания» и выберите локальный генератор либо AI-провайдера.
2. Дождитесь завершения задачи. Интерфейс опрашивает сервер и показывает этап, попытку и стоимость.
3. Проверьте RU/DE-поля и при необходимости отредактируйте карточку.
4. Утвердите карточку.
5. Выберите язык и цветовую схему, затем создайте версию сайта.
6. Откройте preview, скачайте ZIP или экспортируйте профиль в JSON.

Изменение уже утверждённой компании создаёт новую ревизию со статусом `draft`. Ранее созданные сайты продолжают использовать собственные сохранённые снимки.

## Настройка AI

Скопируйте `.env.example` в `.env` и заполните только необходимые переменные:

```dotenv
OPENAI_API_KEY=
OPENAI_MODEL=gpt-6-luna
OPENROUTER_API_KEY=
OPENROUTER_DEFAULT_MODEL=
AI_OPERATION_BUDGET_USD=0.25
AI_MAX_RETRIES=1
AI_REQUEST_TIMEOUT_MS=90000
```

### OpenAI

Серверный каталог разрешает `gpt-6-luna`. Адаптер использует Responses API и Structured Outputs через Zod, после чего повторно запускает доменную проверку. Цена в серверном каталоге соответствует [официальной карточке GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna): `$0.10` за миллион входных и `$0.50` за миллион выходных токенов при стандартной обработке.

### OpenRouter

Каталог моделей загружается сервером с OpenRouter и кешируется на 15 минут. В интерфейс попадают только модели с известной ценой и поддержкой `structured_outputs` или `response_format`. Секретный ключ и исходные ответы провайдера клиенту не возвращаются.

### Бюджет и повторная попытка

До запроса сервер оценивает верхнюю стоимость. Запрос не запускается, если оценка превышает `AI_OPERATION_BUDGET_USD`. После ответа учитываются токены, а для OpenRouter — `usage.cost`, если значение присутствует. Разрешена максимум одна повторная попытка и только при наличии остатка бюджета.

### Локальный генератор

Seeded-генератор не обращается к сети и не требует ключей. Он меняет бренд, город, специализацию, происхождение, продукт, отраслевой контекст и опыт команды, сохраняя ту же каноническую схему.

## Проверки

Все поддерживаемые проверки выполняются в Docker:

```bash
docker compose run --rm test npm test
docker compose run --rm test npm run typecheck
docker compose run --rm test npm run lint
```

Production-сборка и healthcheck:

```bash
docker compose up --build -d
docker compose ps
curl http://localhost:3000/api/health
```

На машине с Node.js 24+ можно выполнить `npm ci` и `npm run dev`.

## HTTP API

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/health` | состояние приложения и SQLite |
| `GET /api/providers` | провайдеры, модели и лимит без ключей |
| `POST /api/generation/companies` | создать фоновую задачу генерации |
| `GET /api/jobs/:id` | этап, попытка, стоимость, результат или безопасная ошибка |
| `GET/POST /api/companies` | список и импорт валидного профиля |
| `GET/PATCH /api/companies/:id` | получить или изменить карточку |
| `POST /api/companies/:id/approve` | утвердить текущую ревизию |
| `GET/POST /api/companies/:id/sites` | версии сайта и создание новой версии |
| `GET /api/companies/:id/export` | скачать канонический JSON |
| `GET /api/sites/:id/download` | скачать автономный ZIP |

Задачи проходят состояния `queued`, `preparing`, `requesting`, `validating`, `retrying`, `saving`/`rendering`, `complete` или `failed`.

## Данные и экспорт

SQLite хранит канонический профиль и снимки сайтов как валидированный JSON. Индексируемые колонки содержат только идентификаторы, статусы, название, ревизию и даты. Полная опубликованная схема находится в [`docs/company-profile.schema.json`](docs/company-profile.schema.json).

ZIP каждой версии содержит только:

- `index.html`, `product.html`, `company.html`;
- `styles.css` и `favicon.svg`;
- локальный `assets/team.png`.

Внешние CSS, шрифты, скрипты и изображения не используются. Форм и несуществующих функций в генерируемом сайте нет.

## Безопасность и инварианты

- API-ключи читаются только на сервере и исключены из Git, API, логов, JSON и ZIP.
- Каждый вход перед записью проходит Zod и доменные валидаторы.
- Проверяются немецкий телефонный код города, пять FAQ, минимум пять сотрудников, RU/DE-поля, уникальные ID и отсутствие шаблонных переменных.
- Сайт создаётся только из утверждённой карточки.
- Preview и ZIP читаются из одного сохранённого каталога артефакта.
- Путь артефакта проверяется на выход за пределы каталога данных.

## Архитектура

Подробное описание компонентов, хранения и границ будущего Nest.js-сервиса находится в [`docs/architecture.md`](docs/architecture.md). Основные слои уже разделены на UI, Route Handlers, доменную модель, AI-адаптеры, хранилище и статический рендерер.

## Ограничения MVP

- один локальный пользователь, без авторизации и ролей;
- только Германия, размеры `small`/`medium` и B2B AI-сервисы для инвестиционных исследований и анализа данных;
- один макет статического сайта с четырьмя цветовыми схемами;
- без облачного деплоя, загрузок, клиентских логотипов, отзывов и контактных форм;
- фоновые задачи выполняются процессом приложения и не предназначены для горизонтального масштабирования;
- доступность и качество внешних моделей зависят от аккаунта и соответствующего провайдера.
